# ADR 006. Сервер в production запускается из исходников на TypeScript

**Статус:** принято · этап 4

## Контекст

Сервер написан на TypeScript и импортирует общий контракт из `shared/types.ts`.
Для образа нужно решить, как он попадает в production: собранным в JavaScript
или как есть.

Node с версии 22.6 умеет снимать типы с `.ts`-файлов, а с 23.6 это поведение
включено по умолчанию. В образе используется `node:26-alpine`.

## Решение

Запускать исходники напрямую: `CMD ["node", "server/src/index.ts"]`.

Из образа исчезает шаг сборки, а вместе с ним — вопросы, которые он тянет за
собой: куда класть артефакты, как не забыть пересобрать, почему стек-трейс
указывает не на тот файл. Исходники в контейнере совпадают с исходниками в
репозитории один в один.

Цена — ограничение на синтаксис: работает только то, что стирается без
генерации кода. `enum`, `namespace` и параметры-свойства конструктора
запрещены. Ограничение включено на уровне компилятора (`erasableSyntaxOnly` в
`server/tsconfig.json`), поэтому нарушение — ошибка типизации, а не сюрприз при
запуске контейнера.

## Альтернативы

**Сборка через `tsc`.** Привычно и снимает ограничение на синтаксис, но добавляет
стадию сборки и каталог артефактов ради семи файлов сервера. Понадобится, если
сервер вырастет или потребуется поддержка старых версий Node.

**Сборка бандлером (esbuild, tsup).** Быстро, но это ещё одна зависимость и
конфигурация ради того же результата.

## Последствия

- Образ сервера не содержит ни компилятора, ни dev-зависимостей: `npm ci
  --omit=dev` ставит только `express`, `cors` и `ws`.
- Клиент собирается иначе, и это не противоречие: там сборка нужна по существу —
  бандлинг, минификация, хеши в именах файлов.
- Проверка типов остаётся отдельной командой `npm run typecheck`; она не является
  частью запуска, и это надо помнить при работе в CI.
